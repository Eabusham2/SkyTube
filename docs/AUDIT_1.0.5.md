# SkyTube 1.0.5 requirement audit

This review traced the complete original request against the published 1.0.4 source at `3c0ab21128c16ff5339d65e0bc93924eb5b9c2dd`, reran its build and tests, and checked the current GitHub release and CI. The original controls, providers, Minecraft target and release gates remain in place. Three concrete issues were reproduced and corrected with targeted changes.

## Corrections from this audit

| Case | Correction and regression coverage |
| --- | --- |
| Cloud slider shows 0% or 100% but saves a nearby fractional opacity | Quantize the submitted cloud opacity to the whole percentage shown, as for the visibility slider. Real minimum-size widget clicks reproduce approximately 0.34% at a displayed 0% and 99.66% at a displayed 100% on the released code; the corrected values are exactly 0 and 1. Direct fractional configuration values remain supported. |
| An earlier rewind is acknowledged after Catch-up is re-enabled | Include an outstanding backward seek in the rewind detector's baseline. Keep the actual iframe position for latency estimation and forward-seek confirmation. The delayed acknowledgment no longer cancels catch-up; a later deliberate iframe rewind still does, and an ignored forward catch-up seek remains retryable. |
| Rewind, Previous, Next or Go live is silently ignored while the iframe starts | Check that the current source/provider is both acknowledged and ready before dispatching these actions. An unavailable action gives immediate native feedback saying it did not run and must be retried. The check is separate from playlist-selection acknowledgments, preserving rapid ready-player navigation. Play/pause intent and preferences still work during startup. |

## Verification

The final production build passed **117 Java tests** and **43 Node tests**, with no failures, errors or skipped cases. All **5 release-verifier test groups** and actionlint checks for all three workflows passed. Each reported failure was reproduced against the released behavior before the correction. An independent player fixture varied the rewind acknowledgment across 125, 750 and 1,450 milliseconds, then checked a later simulated iframe scrub and ignored forward catch-up seeks.

The final combined local Minecraft GPU texture fixture passed **24 playback checkpoints and 5 loading-control cases**, with **21 readable screenshots**. It checked real 0%/100% cloud-slider values, the exact 90%-visible scene, immediate native loading feedback and a ready-player burst containing two J presses and the Go live button. Account-draft resize and world-exit cleanup also passed. A separate local input audit reached all eight registered key handlers; its N case checked the pre-load handler, not a served advertisement. Software OpenGL readbacks confirmed the cloud endpoint's color/depth effect and unchanged pixels outside the mask. Direct fractional cloud settings survived a save/reload.

The account review independently reran six readable/locked synthetic credential-store cases across Linux Secret Service, macOS Keychain and Windows DPAPI, and checked current-video binding and world teardown through the loopback server. It found no additional account defect. These fixtures do not exercise a real OS vault or a Google grant.

The production and sources JARs passed ZIP integrity checks; the production metadata declares version 1.0.5, Minecraft 1.21.11 and a client-only mod. Neither archive contains the separate game-test mod. Linux/Windows main CI and required native Minecraft/MCEF release tests remain publication gates. This patch changes no dependency or workflow. The local texture fixture does not establish native Chromium or external YouTube streaming; required Chromium evidence comes from GitHub CI.

## Provider facts and verification limits

[YouTube documents that privacy-enhanced embeds can show ads](https://support.google.com/youtube/answer/171780?hl=en). [yout-ube describes its service as a redirect to youtube-nocookie.com](https://www.yout-ube.com/). Its advertising claim does not make that destination a guaranteed ad blocker. The implemented choice is labeled as the No-Cookie destination rather than an independent playback backend.

The previous hosted [YouTube diagnosis](https://github.com/Eabusham2/SkyTube/actions/runs/45103518780) displayed a sign-in verification requirement in all three provider selections. The project owner explicitly authorized skipping that external-service check. This audit retains that decision. Native Chromium fixture rendering, provider routing, offline player behavior and local account fixtures are distinct from successfully streaming a real YouTube video.

Real YouTube playback, physical audio output, a particular live broadcast/DVR/chat, real advertisements, live Google consent, real operating-system credential vaults and authenticated posting remain unverified under the required automated checks. OAuth and vault protocols were exercised with local fixtures and synthetic credentials. OAuth authorizes API actions; it does not transfer a Premium browser session into MCEF. The pinned Linux Chromium build played the tested WebM controls but did not support the tested H.264/AAC MP4 control. Rendering against external shader packs and exact translucent/entity silhouettes are outside the measured coverage.
